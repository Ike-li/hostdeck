# 插件

[English](PLUGINS.md)

这份文档是插件的约定：插件文件夹里放什么，`plugin.yaml` 的每个字段，hostdeck 怎么运行插件的程序，程序又该打印什么。它对应 `schema: 1`，首次发布前仍可能变更；发布之后保留什么，见[兼容](#兼容)。清单由 `internal/plugin` 读取；测试会检查它接受的每个字段在这里都写到了，两种语言都查。

[README](../README.zh-CN.md#从源码运行) 里有三个短清单可以照着写；[`examples/`](../examples) 里是完整的插件，其中磁盘空间和后台任务两个的卡片和详情页由脚本生成，macOS 和 Windows 各有一份。

## 文件夹

一个插件是 hostdeck 文件夹下 `plugins/` 里的一个文件夹，里面有一个 `plugin.yaml`。文件夹名就是插件的 ID：侧栏地址用它，`layout.json` 和 `ports.json` 用它作键，CLI 的 `--id` 指的也是它。CLI 接受的 ID 不能为空，不能以点开头，不能含 `/`、`\`、`:`、换行或 NUL，两端也不能有空格。

- 以点开头的文件夹会被跳过。`.disk` 就是停用了的 `disk`，`.trash` 里放的是移入回收区的插件。
- 插件的程序在它自己的文件夹里运行，所以和 `plugin.yaml` 放在一起的脚本直接写文件名就行。
- 插件可以在自己的文件夹里存自己的文件，磁盘变化就把 `config.json` 和 `data/` 存在那里。从回收区清除插件时，这些文件会一起删掉。
- hostdeck 在启动时、在「页面与插件」页每次改动后、以及运行 `hostdeck plugin reload` 时读取插件。`hostdeck plugin validate --from <文件夹>` 按同样的规则检查一个文件夹，不运行任何程序。

## plugin.yaml

一个 YAML 文档。hostdeck 不认识的字段算错误，并指出所在的行，所以拼错的字段会暴露出来，而不是被悄悄忽略。清单有错的插件会显示成一条错误，说明哪里不对；其他插件照常加载。

| 字段 | 类型 | 是否必填 | 含义 |
| --- | --- | --- | --- |
| `schema` | 整数 | 必填 | `1` |
| `name` | 文字 | 必填 | 插件在侧栏、卡片和「页面与插件」页上的名字 |
| `description` | 文字 | | 插件做什么、用之前要改什么；「页面与插件」页会显示 |
| `icon` | 字符串 | | 原样画在名字旁边的小方块里：写一个字符或一个 emoji 就好。不写时用名字的第一个字 |
| `page.proxy` | 地址 | | 本机或局域网上的一个网页界面，通过它自己的转发端口内嵌进控制台 |
| `page.link` | 地址 | | 侧栏这一项在新标签页里打开的网页 |
| `card.interval` | 时长 | 不写时为 `1m` | 一次成功的读数保留多久 |
| `card.http.url` | 地址 | HTTP 卡片必填 | 卡片用 GET 请求的地址；可以含 `${env:NAME}` |
| `card.http.headers` | 字符串映射 | | 请求头；值里可以含 `${env:NAME}` |
| `card.value` | gjson 路径 | HTTP 卡片必填 | 卡片的值在响应里的位置 |
| `card.label` | 文字 | | 和值一起显示 |
| `card.warn` | 阈值 | | 值什么时候变黄 |
| `card.error` | 阈值 | | 值什么时候变红 |
| `card.rows[].name` | 文字 | | 一行的名字 |
| `card.rows[].value` | gjson 路径 | 每行必填 | 这一行的值在响应里的位置 |
| `card.rows[].warn` | 阈值 | | 这一行什么时候变黄 |
| `card.rows[].error` | 阈值 | | 这一行什么时候变红 |
| `card.exec.command` | 程序 | 程序卡片必填 | 打印整张卡片 |
| `card.exec.windows` | 程序 | | 在 Windows 上代替 `command` 运行 |
| `detail.exec.command` | 程序 | 有 `detail` 时必填 | 打印插件详情页的条目 |
| `detail.exec.windows` | 程序 | | 在 Windows 上代替 `command` 运行 |
| `actions.exec.command` | 程序 | 有 `actions` 时必填 | 对详情页上的一个条目执行操作 |
| `actions.exec.windows` | 程序 | | 在 Windows 上代替 `command` 运行 |

各部分怎么组合：

- 插件要有 `name`，并且 `page`、`card`、`detail` 至少有一个。
- `page` 里 `proxy` 和 `link` 恰好写一个。
- `page` 和 `detail` 各自是侧栏的一项，一个插件只有一项：两者不能同时写。两者都可以配一个 `card`。
- `card` 里 `http` 和 `exec` 恰好写一个。`value`、`label`、`warn`、`error`、`rows` 只配 `http`；程序卡片由程序自己打印这些。
- 有 `actions` 就必须有 `detail`，因为操作作用在详情页的某个条目上。

### 值的类型

- **文字**：所有语言共用一个字符串，或者每种语言一个，比如 `{en: Status, zh-CN: 状态}`。语言只有 `en` 和 `zh-CN`，写别的键算错误。页面显示控制台当前的语言；没有就显示英文，再没有就显示写的第一个。
- **地址**：`http` 或 `https`，要有主机名。`page.proxy` 的主机解析出的地址必须全是本机回环、私有或链路本地地址：代理每次连接时都会检查，因为服务收到的 Host 是浏览器发来的 `127.0.0.1:<转发端口>`，互联网上的网站不会应答这样的请求。
- **时长**：按 Go 的写法，比如 `30s`、`5m`、`1h30m`，必须大于零。
- **gjson 路径**：用 [gjson 语法](https://github.com/tidwall/gjson/blob/master/SYNTAX.md)写的、指向 JSON 响应内部的路径。取到的值是 gjson 对找到内容给出的文字，所以数字保留原来的写法，对象就是它的 JSON。
- **阈值**：下面的键恰好写一个：

  | 键 | 值满足它的条件 |
  | --- | --- |
  | `above` | 是数字，并且大于给定的数 |
  | `below` | 是数字，并且小于给定的数 |
  | `equals` | 写法和给定的值相同 |
  | `not` | 写法和给定的值不同 |

  先查 `error` 再查 `warn`，所以两个都满足时显示红色。写了阈值但都不满足时是绿色；没写阈值就没有颜色。对不是数字的值用 `above` 或 `below`，卡片会显示错误，而不是一种颜色。
- **程序**：一个列表，写程序和它的参数，不经过 shell 运行：`[sh, card.sh]`；Windows 上可以是 `[powershell, -NoProfile, -NonInteractive, -ExecutionPolicy, Bypass, -File, card.ps1]`。不带文件夹的程序名到 `PATH` 里找。以 `'@hostdeck'` 开头的列表运行 hostdeck 自带的程序，比如 `['@hostdeck', disk-history, card]`；这个名字永远不会到 `PATH` 里找。

### 密钥：`${env:NAME}`

`${env:NAME}` 只能写在 `card.http.url` 和 `card.http.headers` 的值里，别处都不行。NAME 由字母、数字和下划线组成，不能以数字开头；这两处写别的 `${…}` 算错误。hostdeck 启动时没有设置的变量会让插件显示成错误，并点出变量名。

变量的值只发给服务，不写到任何地方。卡片的错误里它显示成 `***`，错误把它加了引号或按 URL 转义过也一样；短于三个字符的值保持原样，因为隐藏它会把消息里所有这几个字符都藏掉。程序的参数里不会填入变量：程序从自己的环境里读，那就是 hostdeck 的环境。

## HTTP 卡片

- `card.http` 带着 `headers` 用 GET 请求 `url`。它不理会环境里的代理设置，也不跟随重定向：重定向算错误，并写出状态码；2xx 以外的状态码都一样。
- 响应必须是 JSON，最大 4 MiB。`value` 的路径什么都没找到算错误，并写出这条路径；每一行的路径也是这样。
- 一次读数最多 30 秒。总览等 5 秒，之后把卡片显示成还在读取，有旧值就带上旧值，并再次请求。成功的读数保留 `interval` 那么久；失败的不保留，所以服务恢复后马上就能看到。

## 程序

### 程序怎么运行

- 运行 `command`；在 Windows 上，写了 `windows` 就运行它。程序在插件的文件夹里、带着 hostdeck 的环境运行。卡片程序和详情程序不带参数；操作程序多带两个，见[操作程序](#操作程序)。
- 每次运行有 30 秒。到时间后，程序和它启动的所有进程都会被结束：macOS 上用进程组，Windows 上用 Job Object。程序退出时留下还在运行的进程也会被结束；程序退出后，hostdeck 最多再等一秒读它的输出。
- stdout 里恰好是一个 JSON 值，开头可以有 UTF-8 的 BOM；后面除了空白不能再有别的。这里没写到的字段算错误，所以拼错的字段会暴露出来。stdout 只保留前 4 MiB，stderr 只保留前 64 KiB。
- 退出码 0 表示成功。其他退出码都算错误，显示退出码和 stderr 的最后一行，stdout 不读。所以诊断信息写到 stderr；要给人看的失败原因用 `{"error": …}` 打印，退出码仍然是 0。
- Windows PowerShell 5.1 读没有 BOM 的脚本时按系统代码页解码，所以脚本要存成带 BOM 的 UTF-8，并让它输出 UTF-8：示例里写的是 `[Console]::OutputEncoding = New-Object System.Text.UTF8Encoding $false`。它第一次启动可能要好几秒，所以卡片有时会显示成还在读取。

### 卡片程序

卡片程序打印整张卡片：

```json
{"status": "warn", "value": 42, "label": "等待中", "rows": [{"name": "今天失败", "value": 3, "status": "error"}]}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `status` | `ok`、`warn`、`error`，或者不写 | 卡片的颜色；不写就没有颜色 |
| `value` | 字符串或数字 | 卡片的值 |
| `label` | 文字 | 和值一起显示 |
| `rows[].name` | 文字 | 一行的名字 |
| `rows[].value` | 字符串或数字 | 一行的值 |
| `rows[].status` | `ok`、`warn`、`error`，或者不写 | 一行的颜色 |
| `error` | 文字 | 写了它，卡片就把这段话当作插件自己报的错显示出来，其他都不显示 |

写别的状态算错误。

### 详情程序

详情程序打印插件侧栏页面上的条目，或者打印 `{"error": …}`，页面就显示这个错误，不显示条目：

```json
{"items": [{"id": "backup", "name": "每晚备份", "status": "ok", "value": "02:00 运行过", "fields": [{"name": "文件夹", "value": "/Volumes/Backup"}], "log": "02:00 开始\n02:14 完成", "actions": [{"id": "run", "label": {"en": "Run now", "zh-CN": "立即运行"}}]}]}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `presentation` | `compact` 或省略 | 可选的紧凑列表布局；省略保留原有布局 |
| `groups[].id` | 字符串 | 可选分类的唯一非空 ID；`all` 保留给全部 |
| `groups[].label` | 文本 | 非空的分类名称，按给出的顺序展示 |
| `items[].group` | 字符串 | 已声明的分类 ID；提供分类时每条任务必填，启用会话内名称/ID 搜索和带数量的筛选 |
| `items[].id` | 字符串 | 必填，每个条目各不相同；操作程序会收到它 |
| `items[].name` | 文字 | 必填，条目的标题。不写、写成 `null`、空字符串或纯空白，或语言对象里没有非空白文字，都算错误，页面不显示条目。只提供一种语言的非空白文字也可以 |
| `items[].status` | `ok`、`warn`、`error`，或者不写 | 条目的状态，用文字显示 |
| `items[].value` | 字符串、数字或双语文本 | 条目的主要值 |
| `items[].fields[].name` | 文字 | 一个字段的名字 |
| `items[].fields[].value` | 字符串、数字或双语文本 | 一个字段的值 |
| `items[].log` | 字符串 | 显示在「日志最后几行」下面一个可以单独滚动的框里；打印最后几行就好，不要打印整个文件 |
| `items[].actions[].id` | 字符串 | 必填；操作程序会收到它 |
| `items[].actions[].label` | 文字 | 操作按钮上的字 |

### 操作程序

操作按钮要点第二次才执行。之后 hostdeck 先重新运行一次详情程序，只有那个条目仍然提供这个操作时才执行；否则页面说明这一点，并重新读取列表。同一时间只执行一个操作，所有插件都算在内。操作程序的运行方式是 `<命令…> <操作 id> <条目 id>`，即使发起操作的页面关掉了，它也会运行到结束或到时间，免得重启只做了一半。这两个 ID 是详情程序刚刚打印出来的；把它们当作数据，绝不当作代码执行。

程序可以什么都不打印，也可以打印 `{"message": …}`，页面把它显示为结果，或者打印 `{"error": …}`；两者都是文字。什么都不打印时，页面说明操作已完成。过一会儿页面会重新读取详情。

## 兼容

第一个正式版本之前，`schema: 1` 仍可能变更，改动它的提交会写明已有插件要怎么改。从第一个正式版本起，在 `schema: 1` 之内，清单和程序的输出只增加可选的字段和取值；不删除、不改名、不改含义。用了新字段的插件需要认识它的 hostdeck：旧版会拒绝这个插件，并指出那个字段所在的行。不能这样加进去的改动用 `schema: 2`，引入它的版本会说明插件怎么迁移。[ARCHITECTURE.zh-CN.md](ARCHITECTURE.zh-CN.md#约定与兼容) 写了每种约定的规则。

## 信任

插件是被信任的：它们是你自己放进来的文件夹，程序以你的权限运行。控制台的网页不能把程序写进清单；[ARCHITECTURE.zh-CN.md](ARCHITECTURE.zh-CN.md#安全模型) 的安全模型写明了页面上的每种改动能写什么。只从你信任的来源复制插件。

后台任务使用紧凑分类详情。macOS 用系统 plutil 读取配置，展示 PID、配置的参数、启动规则、配置及日志路径；同一任务内重复日志路径去重，每文件最多读取末尾 16 KiB、展示 20 行。Windows 展示服务身份、PID、启动方式、账户、完整命令，并从最近 200 条 Service Control Manager 事件的结构化属性中匹配，每服务最多 20 条。所有日志预览共享单页 512 KiB 预算。配置缺失、日志无法读取、没有匹配事件和截断都作为局部字段说明，不改变任务健康状态和操作权限。原有字符串和数字详情值保持原行为；双语值采用标签相同的 en/zh-CN 文本对象，需要新版 hostdeck。

## 原生 Docker 监控

内置 `docker` 插件使用 `['@hostdeck', docker, card]` 和 `['@hostdeck', docker, detail]`，复用现有卡片和详情 JSON 约定。它需要 hostdeck 的 PATH 中有 Docker 命令行，并且引擎已运行。安装只创建清单，不启动 Docker 或任何容器。

有效 Docker 连接遵循环境优先级，先 `DOCKER_CONTEXT`，再 `DOCKER_HOST`，否则使用选中的 context。插件仅接受本机 Unix socket、`npipe:////./pipe/...` 或字面量回环 TCP 地址。每次引擎命令固定使用已校验的端点，并从子进程环境中移除 context/host 覆盖值。回环 TCP 的 TLS 设置可通过 Docker 现有环境变量提供；不导入 context 专属 TLS 材料。远程、主机名 TCP 和 SSH 端点被拒绝。

详情展示镜像、状态、健康、时间、退出状态、重启策略与次数、端口、网络、挂载和命令参数，不请求环境变量或健康检查输出。总览的运行数量包含健康检查失败但仍在运行的容器；正常未运行一行不含故障。运行中但健康检查失败、异常退出的容器需要处理；正常停止和刚创建的容器不算故障。暂停有独立分类，健康检查启动中会如实说明，不宣称失败。

最近日志合并标准输出和错误输出，请求最后 20 行且不持续跟随，每容器最多保留 16 KiB，单页共享 512 KiB。整页可选日志读取最多五秒，每容器最多一秒。不支持日志的驱动、日志缺失或时间/大小上限产生局部说明，不丢弃容器信息。列表或检查失败则拒绝整次读数，不报告健康的零容器。

Docker 操作使用 `['@hostdeck', docker, action] <操作-id> <条目-id>`。`start` 仅用于已创建/已退出容器；`restart` 仅用于运行中容器，包括健康检查失败但仍在运行的容器。暂停、重启中、移除中、已损坏和未知状态均不提供这两种操作。与其他详情操作一样，需要二次点击确认和成功的重新读取。原生程序还会校验绑定端点的不透明条目 ID，再检查完整 64 字符容器 ID，随后只执行一条启动/重启命令，不退回名称或短 ID。

命令保留 Docker 配置的停止超时。控制台的 30 秒期限仍会结束 CLI 进程树，但 Docker 引擎已接受的操作可能继续。因此 CLI 超时会说明结果尚未确认并提示刷新，不声称成功或已取消。这些操作不新增清单键或保存文件，需要支持 Docker 操作程序的新版二进制。

## 定时脚本任务

内置 `scheduled-tasks` 使用 `@hostdeck tasks card|detail|action` 和独立的 `tasks.json`，字段、持久状态、执行与调度规则统一见 [TASKS.zh-CN.md](TASKS.zh-CN.md)。安装生成空任务列表，读取不启动脚本。命令只在本地配置，脚本输出普通日志，不受插件程序的 JSON 输出要求限制。现有插件和文件无需迁移，也没有新增清单字段或公开 CLI 命令。

启动及显式重载整份校验配置；失败保留上一份有效配置及现有运行，并通过插件诊断和既有重载失败结果报告。每秒检查 Cron 或固定间隔的到期任务，使用内置时区数据。间隔锚点、游标、暂停状态及错过统计持久保存；重启、重载和恢复不补跑，时钟回退不重复执行。每任务互斥，最多四并发，无等待队列和自动重试。手动与自动触发共用执行入口；暂停只阻止后续启动，停止绑定具体运行且不暂停以后计划。

中立的进程层启动同一二进制的私有工作进程，先加入进程组或 Windows Job Object，再持久保存启动记录与身份，最后才通过私有管道允许启动脚本。脚本输出与控制消息分离；主进程管道断开会清理脚本进程树。既有插件程序仍保留 30 秒与严格 JSON 规则。

既有检查 Origin 的详情操作只写该插件的 `data/state.json`、日志、所有者锁和未发布的临时状态文件，不写命令、其他插件或布局。操作系统锁排除第二写入者；损坏状态拒绝覆盖。重启将遗留运行标为中断并暂停，明确恢复前只查询旧进程组／Job Object 是否清空，不结束旧 PID。清理未确认的身份继续占用名额。移除、停用及正常退出先取消运行并释放资源。历史淘汰先原子保存引用变更，再删除日志；无法落盘的结果显示中断和存储错误。日志有界且持续排空，遮蔽引用环境密钥；详情展示最近十次运行及有界预览。

安装包含停用的 `tasks.example.json`，空原生详情说明本地设置步骤。既有插件代理提示词包含完整任务定义及当前控制台的备份／重载命令。保留的设置／诊断行、观察结果及受所有者保护的挂起规则见 TASKS。
