# 设计规范

[English](DESIGN.md)

这份规范是 hostdeck 控制台界面的统一依据：设计新视图、改组件、换主题，都先查这里。它不另起一套样式，而是把 `web/style.css` 已经在用的令牌和组件写成规则：每条规则落在哪个选择器、由哪个测试守住，每个重要取舍为什么这样定。

令牌的唯一来源是 `web/style.css` 顶部的 `:root`。本文和代码不一致时，以代码和守住它的测试为准，然后改本文。

每一节都带一个状态：

| 标记 | 含义 |
| --- | --- |
| 【已实现】 | 代码已经是这样，写明选择器，改它要同时改代码和测试 |
| 【缺口】 | 代码目前不满足本规范；附录 A 写明还没做的部分和原因 |
| 【预留】 | 产品还没有这个组件，先定好规则，第一次用到时照做 |

## 0 假设与原则

### 0.1 假设

| 项 | 采用的假设 | 依据 |
| --- | --- | --- |
| 品牌色 | 没有品牌规范；现有主色 `#2b64c6`（深色 `#6c9cf0`）就是品牌色 | 仓库里没有品牌资产，主色已上线并通过对比度测试 |
| 目标用户 | 一个人在自己的 Mac 或 Windows 电脑上管理本机服务，懂技术，常同时开着终端 | README「What it will be」 |
| 设备 | 桌面浏览器，Chrome 和 Edge 有测试，Firefox 和 Safari 尽力；窗口可以拉窄，但不面向手机 | README「Not planned」排除了其他设备访问；AGENTS 的 M0 决定 |
| 技术栈 | 一个 Go 程序内嵌页面；`web/` 是纯 ES module，没有构建步骤、没有 npm；一份 `style.css`；门禁是 Go 测试和真实浏览器测试 | AGENTS.md「How work is done」 |
| 语言 | 英文和简体中文，可切换，两份词典键一致 | `web/i18n/*.json`，`web/i18n_test.go` |
| 主题 | 跟随系统的浅色和深色，没有手动切换 | 还没有设置页 |
| 字体 | 没有品牌字体，用系统字体 | 单个二进制、离线可用，不下载字体 |

### 0.2 原则

1. **代码就是令牌源。** 浏览器直接读 CSS 自定义属性，Go 测试用同一个解析器读它们。理由：没有构建步骤，就不该有第二份需要同步的源。
2. **一套刻度。** 间距、字号、行高、圆角、时长都只能取刻度上的值，测试会拒绝刻度外的字面量。理由：零散的 10px、17px 会各自漂移。
3. **状态不只靠颜色。** 每个颜色表达的状态都同时有文字或形状。理由：红绿色弱的人也要看得懂哪个服务挂了。
4. **不发明产品没有的行为。** 规范只规定已有交互的样子；新交互先作为产品切片提出。理由：设计规范不是需求文档。
5. **能测的规则都要有测试。** 第 6.4 节列出每条规则由哪个测试守住，没有守住的就是缺口。

## 1 设计基础

### 1.1 色彩

#### 1.1.1 主题色【已实现】

一套主题只由下面 14 个颜色组成。换主题只改这 14 个值，其余颜色都由它们派生。

| 令牌 | 角色 | 浅色 | 深色 | 文字对比度（在 `--panel` 上，浅 / 深） |
| --- | --- | --- | --- | --- |
| `--bg` | 页面底色，次级表面（日志、分段控件底） | `#f6f7f9` | `#15171b` | — |
| `--panel` | 卡片、侧栏、面板、弹窗的表面 | `#ffffff` | `#1e2126` | — |
| `--text` | 正文、标题 | `#1c1f24` | `#e7e9ec` | 16.52 / 13.27 |
| `--muted` | 次要文字、字段名、提示、未选中的图标 | `#606975` | `#9aa1ab` | 5.56 / 6.20 |
| `--line` | 分隔线、卡片和按钮的默认边框 | `#e3e6ea` | `#2d3138` | 非文字，见 5.1 |
| `--line-strong` | 卡片和行悬停时的边框 | `#c9ced6` | `#3d434d` | 非文字，见 5.1 |
| `--line-control` | 输入框的边、还没有消息的状态点 | `#868d98` | `#686e78` | 非文字：3.35 / 3.14（在 `--bg` 上 3.12 / 3.50） |
| `--accent` | 主色：主按钮底、选中项、焦点环、按钮悬停边框 | `#2b64c6` | `#6c9cf0` | 5.61 / 5.88 |
| `--accent-strong` | 主按钮悬停 | `#2556a9` | `#8ab0f5` | — |
| `--accent-pressed` | 主按钮按下 | `#1f4988` | `#a3c3f8` | — |
| `--on-accent` | 主色底上的文字 | `#ffffff` | `#15171b` | 在 `--accent` 上 5.61 / 6.54 |
| `--ok` | 正常、运行中 | `#247a46` | `#4cc27f` | 5.32 / 7.17 |
| `--warn` | 需要注意 | `#946313` | `#e0a83a` | 5.18 / 7.56 |
| `--error` | 出错、危险操作 | `#bf3636` | `#ef6b6b` | 5.53 / 5.37 |

题目要求的四类颜色在这里的对应：

- **主色**：`--accent` 一族（`-strong`、`-pressed`、`--on-accent`）。
- **辅助色**：不设。理由：绿、黄、红已经代表状态，再加一种彩色，用户会把它当成某种状态；分组靠标题、间距和中性色表面。
- **语义色**：`--ok`、`--warn`、`--error`。不设单独的信息色，信息提示用主色的浅底（`--tint-accent`）。理由：蓝色只表示控制台自己的话和选中，不和状态色抢含义。
- **中性色**：`--bg`、`--panel`、`--text`、`--muted`、`--line`、`--line-strong`、`--line-control`，色阶见 1.1.2。

深色主题的两条规则：

- 主色变亮，`--on-accent` 变成深色。理由：深底上的蓝要变亮才有 4.5:1，主按钮于是成了亮底深字。
- 悬停和按下在浅色下逐级变暗，在深色下逐级变亮。理由：方向始终是离背景更远，按下比悬停更明显。

#### 1.1.3 派生色【已实现】

派生色用 `color-mix(in srgb, …)` 从主题色混出来，换主题时自动跟着变。

| 令牌 | 配方 | 用在 |
| --- | --- | --- |
| `--tint-accent` | `--accent` 10% + `--panel` | 结果提示 `.note`、`.detail-note`、`.catalog-note` |
| `--tint-active` | `--accent` 14% + 透明 | 选中的导航行 |
| `--tint-pressed` | `--accent` 22% + 透明 | 所有可按元素的按下态 |
| `--tint-error-soft` | `--error` 14% + 透明 | 全局错误横幅 |
| `--tint-error-hover` | `--error` 12% + 透明 | 待确认按钮在指针下；14% 会让红字低于 4.5:1 |
| `--tint-error-panel` | `--error` 10% + `--panel` | `[data-kind="error"]` 提示、面板里的待确认项 |
| `--tint-card-hover` | `--text` 3% + `--panel` | 可点卡片的悬停 |
| `--tint-row-hover` | `--text` 4% + `--panel` | 管理行的悬停 |
| `--tint-status`（`.pill` 内局部） | `--status` 10% + 透明 | 状态胶囊底色；更浓会让 12px 的状态词低于 4.5:1 |
| `--opacity-disabled` | `.5` | 禁用控件 |

悬停用中性色混出来，不用主色。理由：悬停不能看起来像选中（`.card:hover` 的注释写的就是这个）。

#### 1.1.4 遮罩与阴影色【已实现】

| 令牌 | 值 | 用在 |
| --- | --- | --- |
| `--scrim` | `#0005` | 窄窗抽屉后面的遮罩 |
| `--scrim-dialog` | `#11182770` | 弹窗的 `::backdrop` |

两套主题用同一组值。理由：遮罩要压暗下面的内容，黑色半透明在两种底色上都能做到。

### 1.2 字体【已实现】

**字体族**：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。前三个照顾西文，后两个分别是 macOS 和 Windows 上的中文回退。理由：两个平台都用原生字体，不下载、离线可用。

**等宽**：`ui-monospace, monospace`，用在提示词文本框；`code` 和 `pre` 用浏览器默认的等宽字体。

**字号**：8 级，每级都有固定用途。

| 令牌 | 字号 | 行高 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| `--text-xs` | 12px | 1.5 | 400 | 读取时间、状态胶囊、插件类型、管理行的字段小标签 |
| `--text-sm` | 13px | 1.5 / 1.65 | 400 | 按钮文字、表单标签、提示、卡片明细行、详情字段、说明文字 |
| `--text-base` | 14px | 1.5 | 400 | 输入框、操作面板菜单项、卡片地址、管理页导语、接入教程正文 |
| `--text-md` | 15px | 1.5 | 400 / 600 | 正文（`body` 默认）；卡片名、小标题 `h3`、加号卡片标题用 600 |
| `--text-lg` | 16px | 1.5 | 600 | 品牌名、区块标题（`h2.catalog-heading`）、服务名、详情名 |
| `--text-xl` | 20px | 1.5 | 600 | 弹窗标题 |
| `--text-2xl` | 24px | 1.5 | 600 | 页面标题 `h1`、详情主数值 |
| `--text-3xl` | 32px | 1.25 | 600 | 卡片主数值；加号卡片的「+」用 400、行高 1 |

**行高**：`--leading-tight` 1.25 只给大数值，`--leading-normal` 1.5 是全局默认，`--leading-relaxed` 1.65 给多行说明和等宽长文本。只有图标字形可以写 `line-height: 1`。理由：说明文字常有两三行，行距放宽更好读；数值只有一行，行距收紧才不会把卡片撑高。

**字重**：只用三种。400 是默认；600（`--weight-semibold`）用于标题、名称、数值和管理行的状态文字；700（`--weight-bold`）只用于品牌标志。理由：只靠一种加粗来区分层级，层级才一目了然。基础规则 `:is(h2, h3, h4, strong, b)` 统一设成 600，`h1` 在自己的规则里设，所以新加的标题不会退回浏览器默认的 700。

**数字**：卡片主数值用 `font-variant-numeric: tabular-nums` 和 `letter-spacing: -.025em`。理由：数字刷新时宽度不跳，32px 的大数字收紧一点更紧凑。

正文 15px，控件文字 13–14px。理由：读的东西比点的东西大一级，扫一眼就分得开内容和控件。

### 1.3 间距【已实现】

只有一套四点刻度。

| 令牌 | 值 | 典型用途 |
| --- | --- | --- |
| — | 0 | 去掉默认外边距 |
| `--space-1` | 4px | 按钮纵向内边距、胶囊内边距、明细行上下、分段控件的间隙、导航行之间 |
| `--space-2` | 8px | 图标和文字之间、按钮之间、字段标签和输入框之间、面板内边距 |
| `--space-3` | 12px | 按钮横向内边距、卡片内各块之间、侧栏横向内边距、提示条内边距 |
| `--space-4` | 16px | 卡片内边距、卡片之间、窄窗页面边距、详情块之间 |
| `--space-5` | 24px | 区块之间、详情条目和弹窗的内边距、页面上下边距、加号卡片内边距 |
| `--space-6` | 32px | 宽窗页面左右边距、管理页大区块之间 |
| `--space-7` | 48px | 暂时没有用处；它是刻度上的一档，所以保留（见 2.5） |
| `--space-8` | 64px | 锚点滚动的顶部留白（`#catalog-add` 的 `scroll-margin-top`） |

规则：

- `margin`、`padding`、`gap` 里的 px 字面量只能是 0 或刻度上的值；其余一律写 `var(--space-*)`。
- 负间距写 `calc(var(--space-2) * -1)`，不写 `-8px`。
- 相关的元素靠得近（4–8px），不相关的分开（16–24px）。理由：间距本身就是分组，用不着再画线。

### 1.4 圆角【已实现】

| 令牌 | 值 | 用在 |
| --- | --- | --- |
| `--radius-sm` | 6px | 按钮、分段按钮、导航小图标、面板菜单项、代码块、跳转链接 |
| `--radius-md` | 8px | 输入框、导航行、提示条、更多按钮、分段控件外框 |
| `--radius-lg` | 12px | 卡片、操作面板、添加表单、详情条目、管理行 |
| `--radius-xl` | 16px | 弹窗 |
| `--radius-full` | 999px | 状态胶囊、能力标签 |
| 50% | — | 状态点、加号圆 |

内层的圆角比外层小：面板 12px 里的菜单项是 6px，分段控件 8px 里的按钮是 6px。理由：内外圆角相同，嵌套的角会显得鼓出来。容器越大圆角越大，弹窗最大，层级一眼看得出。

### 1.5 层级、阴影与叠放【已实现】

| 层 | 表面 | 阴影 | 边框 | 例 |
| --- | --- | --- | --- | --- |
| 0 页面 | `--bg` | 无 | — | 总览底、详情页底 |
| 1 卡片 | `--panel` | 无；可点卡片悬停时 `--shadow-card-lift` `0 4px 16px #0002` | 1px `--line` | 卡片、管理行、详情条目、侧栏 |
| 2 浮层 | `--panel` | `--shadow-popover` `0 8px 32px #0002` | 1px `--line` | 更多操作面板 |
| 3 弹窗 | `--panel` | `--shadow-dialog` `0 24px 80px #0003` | 1px `--line` | 编辑弹窗，下面压 `--scrim-dialog` |

卡片平时是平的，只有点下去会跳转的卡片在悬停时抬起。理由：一屏卡片要安静，抬起来的那张就是马上要打开的那张。

`z-index` 只有四个值：`--z-backdrop` 10（抽屉遮罩）、`--z-drawer` 20（抽屉）、`--z-header` 30（窄窗顶栏）、`--z-skip` 40（跳转链接）。操作面板和弹窗用浏览器的 top layer（`popover`、`<dialog>`），不写 `z-index`。理由：top layer 天然高于一切，也不会被滚动容器裁掉。

### 1.6 边框【已实现】

| 用法 | 取值 |
| --- | --- |
| 默认边框和分隔线 | 1px solid `--line` |
| 输入框的边 | 1px solid `--line-control`，悬停时 `--muted` |
| 悬停 | 卡片和行的边框换成 `--line-strong`；按钮换成 `--accent` |
| 加号卡片 | 1px dashed `--line`，悬停变 `--accent` |
| 状态 | 卡片边框换成 `--warn` 或 `--error`，左侧另画一条 3px（`--rail-w`）的状态条 |
| 焦点 | 2px solid `--accent` 的 outline，偏移 3px |
| 连不上的状态点 | 2px solid `--error` 的圆环，中间透明 |

状态条是画出来的（`::before`，绝对定位），不占布局。理由：有没有状态，卡片里的数字都留在原位。

输入框用比 `--line` 深的 `--line-control`。理由：WCAG 1.4.11 要求标明「这里能输入」的那条边至少 3:1，而 `--line` 只有 1.25:1；按钮有文字、卡片有内容，不需要 3:1 的边，继续用安静的 `--line`。

### 1.7 动效【已实现】

| 令牌 | 值 | 用在 |
| --- | --- | --- |
| `--dur-fast` | 120ms | 悬停和按下的颜色变化、操作面板淡入、跳转链接滑入 |
| `--dur-base` | 200ms | 抽屉滑入、弹窗淡入、提示条淡入 |
| `--dur-slow` | 320ms | 暂时没有用处；刻度上的一档，保留 |
| `--ease-standard` | `cubic-bezier(.2, 0, 0, 1)` | 所有过渡；唯一的曲线 |

规则：

- 过渡必须写出属性名，不能写 `all`；时长只能用 `--dur-*`，缓动只能用 `--ease-standard`。理由：`all` 会让测试刚读到的属性还在动画中途。
- 出现用 `@starting-style` 淡入，而且只改 `opacity`。理由：面板按测量出的像素定位，弹窗打开那一刻要量尺寸，动 `transform` 或尺寸会量错。
- 离开立刻消失，不做退出动画（抽屉关闭时也一样），所以没有退出曲线。理由：还在退场的抽屉仍然盖着页面，会吞掉用户想点下面内容的那一下。
- `prefers-reduced-motion: reduce` 把三个时长归零，并用 `*` 兜底把所有过渡和动画的时长设为 0。

交互时长写在 `web/state.js`，也算令牌：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `ARMED_FOR` | 4000ms | 危险按钮第一次点击后，等第二次点击的时长 |
| `LAYOUT_NOTE_FOR` | 8000ms | 「布局已保存」和撤销在无操作 8 秒后关闭，指针或焦点停在上面时暂停计时 |
| `PENDING_AGAIN` | 2000ms | 还在读取的卡片，隔多久再请求一次 |
| `STATUS_EVERY` | 15000ms | 侧栏状态点刷新间隔 |
| `SEARCH_AFTER` | 10 | 插件超过 10 个才显示搜索框 |

详情页的操作结果提示在 8 秒后关闭（`web/monitor.js`）。

### 1.8 栅格与断点【已实现】

不用 12 栏栅格。理由：界面只有卡片网格和列表两种排法，栏数由内容的最小宽度决定，比固定栏数更稳。

**应用骨架**：`grid-template-columns: 240px minmax(0, 1fr)`，高 `100vh`。侧栏固定 240px（`--sidebar-w`），插件列表自己滚动。

**内容区**：上下边距 24px，左右 32px；窄窗四边都是 16px。**内容不设最大宽度**，总览和插件页铺满窗口。理由：这是已确认的产品决定（和 homedeck 一致），宽屏右侧不留空白。

**卡片网格**：

```css
grid-template-columns: repeat(auto-fill, minmax(max(min(var(--card-min), 100%), (100% - (var(--cards-per-row) - 1) * var(--space-4)) / var(--cards-per-row)), 1fr));
gap: var(--space-4);
```

每列不窄于 220px（`--card-min`），一行最多 4 张（`--cards-per-row`）。窗口再宽，卡片变宽，不加第五列。加宽的卡片跨 2 列；网格容器窄于 455px（两列 220px 加一个间隙）时退回 1 列。理由：卡片太宽，数字和标签离得太远；太多列又扫不过来。

**回收区卡片网格**（`#catalog .cards`）：每列至少 280px（`--card-min-catalog`），顶端对齐，不强制等高。

**断点**：

| 条件 | 变化 |
| --- | --- |
| 视口 ≤ 640px | 侧栏变成 48px 顶栏加抽屉；页面边距 16px；管理行变成单列；详情字段名放到值的上方 |
| 视口 ≤ 1100px | 管理行从 4 列变成 2 列 |
| 卡片容器 ≤ 455px | 加宽卡片退回 1 列（容器查询） |

视口级的布局用媒体查询，组件内部的适配用容器查询。新增断点要先说明现有两个为什么不够。理由：两个断点就能覆盖一个桌面浏览器窗口的宽窄，断点越多越难测全。

**验证宽度**：520、768、1280、2964px，两种语言都测。Headless Chrome 最窄按 500px 排版，所以窄窗验证用 520px。

## 2 设计令牌

### 2.1 位置与格式【已实现】

- 令牌就是 `web/style.css` 第一个 `:root` 块里的 CSS 自定义属性：浅色主题和所有刻度。
- 深色主题在唯一一个 `@media (prefers-color-scheme: dark)` 的 `:root` 块里，只覆盖主题色。
- 减少动效在唯一一个 `@media (prefers-reduced-motion: reduce)` 的 `:root` 块里，只覆盖时长。
- 机器读取用 `web/assets_test.go` 里现成的解析器（`collectCSSRules`、`themeTokens`）。新工具要读令牌，就复用它，不要另写一个。

**不另建 `tokens.json`。** 理由：现在只有浏览器和 Go 测试会读令牌，两者都直接读 CSS；多一份 JSON 就要么配一个生成器，要么配一个同步测试。等到真有读 JSON 的东西（比如 M3 的桌面外壳要画原生颜色），再在 `web/` 里加一个 golden 文件测试，从同一个解析器导出 JSON，用 `go test ./web -run TestTokens -update` 更新。那时 CSS 仍然是唯一来源。

### 2.2 层级

| 层 | 内容 | 数量 | 谁能改 |
| --- | --- | --- | --- |
| L1 主题色 | `--bg` … `--error`，见 1.1.1 | 14 个，每个分浅色和深色 | 换主题时改 |
| L2 派生色 | `--tint-*`、`--opacity-disabled`、`--shadow-*`、`--scrim*` | 14 个 | 几乎不改；改配方要重测对比度 |
| L3 刻度 | `--space-*`、`--text-*`、`--leading-*`、`--weight-*`、`--radius-*`、`--dur-*`、`--ease-standard`、`--z-*` | 34 个 | 改了全站都变，测试里写着每个值 |
| L4 组件尺寸 | `--control-h`、`--icon-*`、`--sidebar-w`、`--card-min`、`--cards-per-row` 等 | 20 个 | 改对应组件时改 |
| 运行时 | `--status`（由 `[data-status]` 设置）、`.pill` 内的 `--tint-status` | 2 个 | 不手写 |

组件只读 L1 到 L4 的令牌，不写颜色、字号、行高、字重、间距、圆角、时长和缓动的字面量。整份样式表里，颜色字面量只出现在两个 `:root` 块里（`TestColoursAreWrittenOnlyInTheThemeBlocks`）。

### 2.3 命名【已实现】

- 刻度令牌写成 `--类别-档位`：`--space-3`、`--text-sm`、`--radius-lg`、`--dur-fast`。档位用数字（间距）或 T 恤尺码（字号、圆角、图标），一类里只用一种写法。
- 主题色直接用角色名，没有 `--color-` 前缀：`--bg`、`--panel`、`--text`、`--muted`、`--line`、`--accent`、`--ok`。理由：整份样式表和对比度测试都在用这些名字，加前缀不会让界面有任何变化。
- 后缀表示同一角色的递进：`-strong`（悬停）、`-pressed`（按下）。
- `on-` 前缀表示放在某个填充色上的前景色：`--on-accent`。
- `tint-` 前缀表示派生的浅底：`--tint-active`。
- 组件尺寸用 `-w`、`-h`、`-min`、`-max` 结尾：`--sidebar-w`、`--topbar-h`、`--card-min`、`--detail-log-max`。
- 运行时由属性驱动的令牌，在组件里读的时候带回退值：`var(--status, var(--muted))`。

### 2.4 换主题

一套主题就是 14 个 L1 颜色各给一个浅色值和一个深色值，L2 到 L4 不动，派生色会自己跟上。所谓「一键替换」，就是替换 `style.css` 里的两个 `:root` 颜色块，步骤是：

1. 改浅色 `:root` 的 14 个颜色和深色块里对应的 14 个。
2. 跑 `go test -short ./web`，三个对比度门禁要全过（见 5.1）。
3. 跑 `HOSTDECK_E2E=1 go test -count=1 ./e2e/`，在 520px 和 1280px、两种语言下看截图。
4. 把 1.1.1 的表格和 5.1 的实测值更新进本文。

【预留】让用户自己选主题需要一个设置页，目前没有，所以暂不做。真要做时：在 `<html>` 上加 `data-theme="名字"`，每个主题写一个 `:root[data-theme="名字"]` 块，只放那 14 个颜色；选择存在 `localStorage`，和 `hostdeck.lang` 一样。注意 `TestTheStyleSheetKeepsOneLayerWithNoDuplicatedSelectors` 不允许出现只在深色下定义的令牌，新主题块也要遵守这一点：主题只能覆盖已有的令牌。

### 2.5 增删令牌

- 新值至少有两处要用，或者有测试要按它检查，才建令牌；只用一次的几何尺寸可以直接作为组件令牌（如 `--editor-w`）。
- 先写在浅色 `:root`；深色块只能覆盖 L1 颜色。
- 改刻度（间距、字号、行高、字重、圆角）要同时改 `web/assets_test.go` 里写死的刻度表，放在同一个 commit 里。
- 刻度上的档位即使暂时没人用也保留，比如 `--space-7` 和 `--dur-slow`。理由：刻度说明的是哪些值允许用；删掉 48px，32px 和 64px 之间就空了，下一个需要 48px 的地方又得把它加回来。
- 不在刻度上的令牌没人用就删。`--ease-exit` 就是这样删掉的：离开不做动画，退出曲线永远用不上。

## 3 组件规范

### 3.0 通用状态【已实现】

| 状态 | 视觉 | 怎么表达 |
| --- | --- | --- |
| 默认 | 见各组件 | — |
| 悬停 | 中性浅底，或边框加深；按钮边框变主色；禁用的控件不响应 | `:hover:not(:disabled)` |
| 按下 | `--tint-pressed` 底 | `:active` |
| 选中 | `--tint-active` 底，或主色文字加 `--panel` 底（分段控件） | `aria-current`、`aria-pressed`、`aria-expanded` |
| 焦点 | 2px `--accent` outline，偏移 3px | 全局 `:focus-visible` |
| 禁用 | 不透明度 0.5，光标恢复默认 | 原生 `:disabled` |
| 加载 | 控件禁用，文字换成进行中的说法，容器带 `aria-busy="true"` | 不用转圈 |
| 错误 | `--error` 文字，或边框加 `--tint-error-panel` 底 | `[data-kind="error"]`、`[data-status="error"]` |
| 待确认 | `--error` 边框和文字，悬停 `--tint-error-hover` | `.armed`，4 秒后复原 |

状态尽量用原生属性或 ARIA 属性表达，样式选择器去匹配这些属性。理由：屏幕阅读器读到的状态和眼睛看到的状态来自同一个属性，不会对不上。

按钮的三条悬停规则都写成 `:hover:not(:disabled)`。理由：按不了的按钮在指针下变色，看起来就像能按（`TestADisabledButtonDoesNotAnswerThePointer`）。

### 3.1 按钮【已实现】

**尺寸**：只有一种。最小高度 44px，内边距 4px 12px，字号 13px，圆角 6px，边框 1px。理由：控件都是 44px，界面密度就靠字号和间距来调，不靠多套按钮尺寸。

| 变体 | 选择器 | 默认 | 悬停 | 按下 | 选中 | 禁用 | 加载 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 次要（默认） | `.btn` | `--panel` 底，`--line` 边框，`--text` 字 | 边框 `--accent` | `--tint-pressed` 底 | 不适用 | 0.5 不透明，不响应悬停 | 禁用，文字改为「刷新中…」之类 |
| 主要 | `.btn.primary` | `--accent` 底和边框，`--on-accent` 字 | `--accent-strong` | `--accent-pressed` | 不适用 | 0.5 不透明，不响应悬停 | 同上 |
| 待确认 | `.btn.armed` | `--error` 边框和字 | `--tint-error-hover` 底 | — | — | — | — |
| 图标 | `.more-trigger` | 44×44，透明底和边框，`--muted` 色，字形 24px，圆角 8px | `--bg` 底，`--line` 边框，`--text` 色 | `--tint-pressed` | `aria-expanded="true"` 与悬停相同 | — | — |
| 分段 | `.lang button` | 透明，`--muted` 字，13px，内边距 4px 8px，圆角 6px | 边框 `--line-strong`，字 `--text` | `--tint-pressed` | `aria-pressed="true"`：`--panel` 底，`--accent` 字，`--line` 边框 | — | — |

分段控件的外框：内边距 4px，间隙 4px，1px `--line` 边框，圆角 8px，`--bg` 底。

使用约束：

- 一个区域最多一个主要按钮：总览头部是「刷新」，管理页头部是「添加内容」，弹窗里是「保存」。理由：主要按钮只有一个时，才能一眼看出这里最该做什么。
- 主要按钮放在同组按钮的最后：总览头部是「重置布局」在前、「刷新」在后，弹窗是「取消」在前、「保存」在后。
- 按钮文字以动词开头（刷新、撤销、添加、保存、编辑）；进行中时禁用，文字换成「刷新中…」「正在保存…」。
- 危险操作（移入回收区、彻底清除、清除缓存）不常驻红色按钮。第一次点击进入待确认态，按钮文字换成确认的说法，4 秒内再点一次才执行；双击算一次手势，不算确认。理由：不弹确认框打断操作，也不怕误点。
- 只有图标的按钮必须有 `aria-label`，并说明作用对象，例如「Grafana 的更多操作」。
- 按钮里的文字可以换行（详情操作按钮允许多行），但不能被截断。

### 3.2 输入框【已实现】

**结构**：可见的标签在上，输入框在中，提示在下。

| 部分 | 取值 |
| --- | --- |
| 标签 `.edit-field` | 纵向排列，间隙 8px，13px，`--muted` |
| 输入框 | 最小高度 44px，宽 100%，内边距 8px 12px，14px，1px `--line-control` 边框，圆角 8px，`--panel` 底，`--text` 字 |
| 悬停 | 边框 `--muted`（获得焦点时不变） |
| 焦点 | 全局焦点环 |
| 禁用 | 0.5 不透明 |
| 提示 `.page-hint` | 上边距 8px，13px，`--muted`；用 `aria-describedby` 关联到它说明的控件（如「内嵌 / 链接」下拉） |
| 错误 | 见下文 |

**类型**：

- 文本：名称等。
- 网址：`type="text"` 加 `inputmode="url"`，不用 `type="url"`。理由：要能接受不带协议的 `127.0.0.1:8080`。地址类输入同时关掉 `autocomplete` 和 `spellcheck`。
- 搜索：`type="search"`，最大宽度 360px，插件超过 10 个时才出现。
- 只读的长文本：等宽 13px，行高 1.65，最小高度 180px，只能纵向拉伸。

**添加表单里的宽度**：字段按 `flex: 1 1 160px` 排，地址字段是 `flex: 2 1 260px`，窄了自动换行。

**约束**：

- 占位文字只能是示例，不能代替标签。
- 必填用原生 `required` 和 `reportValidity()`，比如名称不能为空。

**错误**：服务器拒绝时，错误显示在整个表单旁边的提示里（`[data-kind="error"]`，`role="alert"`），文字本身点明是哪个字段出了问题，比如「这不是网址」。

【预留】错误还没有落到具体字段上。等到有一个错误码只属于某个字段、而文字说不清是哪个字段时，再在该字段上加 `aria-invalid="true"`，边框换成 `--error`，并用 `aria-describedby` 关联到错误文字。理由：现在的错误文字已经满足 WCAG 3.3.1（用文字指出出错的地方），提前做只会多一套没人用的状态。

### 3.3 下拉【已实现】

下拉在这里有两种，用途不同：

**选择**：用原生 `<select>`，样式和输入框一样（例如添加表单的「内嵌 / 链接」）。不自己做 listbox 或 combobox。理由：原生控件自带键盘操作、屏幕阅读器支持和系统的选项弹层，两个平台都可靠。

**操作菜单**（「更多操作」，`.action-panel`）：

| 部分 | 取值 |
| --- | --- |
| 触发 | `.more-trigger`，见 3.1，带 `aria-expanded` |
| 面板 | `popover="manual"`，`position: fixed`；内边距 8px；最小宽度 176px；最大宽度为视口宽减 16px，最大高度为视口高减 16px，超出滚动；1px `--line`；圆角 12px；`--panel`；`--shadow-popover` |
| 位置 | 右边和触发按钮对齐，在按钮下方 4px；下方放不下就翻到上方；离视口边缘至少 8px |
| 菜单项 | 宽度占满，最小高度 44px，内边距 8px 12px，14px，左对齐，圆角 6px；悬停 `--bg`，按下 `--tint-pressed` |
| 危险项 | `--error` 文字；待确认时 `--tint-error-panel` 底 |
| 出现 | 淡入 120ms |

**行为**：Escape 关闭面板并把焦点还给触发按钮；滚动使触发按钮离开视口时，面板自动关闭。面板关闭时，里面的项不在 Tab 顺序里。

**约束**：菜单只放不常用的操作，常用的直接放在行上（例如管理行的「打开」「编辑」）。第一次点击危险项时面板保持打开，让用户在原地完成确认。

### 3.4 表格【预留】

现在没有 `<table>`。数据按三种方式展示：卡片明细行（`.rows`）、详情字段（`<dl>` 两列网格）、管理列表（网格行）。M1 的「端口和进程」「Docker 容器」可能会第一次用到表格。

什么时候用表格：至少 3 列，而且需要跨行比较同一列。否则用 `<dl>` 或行列表。

| 部分 | 取值 |
| --- | --- |
| 容器 | 放在卡片表面里：1px `--line`，圆角 12px；内容太宽时横向滚动，滚动区可以用键盘聚焦 |
| 表头 | 13px，600，`--muted`（在 `--panel` 上 5.56:1），底边 1px `--line`；表格在有限高度内滚动时表头 `position: sticky`，底色 `--panel` |
| 单元格 | 内边距 8px 12px，13px，行高 1.5，左对齐；行底边 1px `--line`，最后一行没有 |
| 数字列 | 右对齐，`tabular-nums` |
| 状态列 | 用状态胶囊（3.7），不要只放一个色点 |
| 行内操作 | 放在最后一列，最多一个直接按钮，其余收进「更多操作」；有操作的行最小高度 44px |
| 悬停 | 只有整行可点时才用 `--tint-row-hover` |
| 斑马纹 | 不用。理由：已经有分隔线，斑马纹再和悬停的浅底叠在一起会乱 |
| 窄窗 ≤ 640px | 每行变成一个 `<dl>` 块，字段名在上，和详情字段的窄窗排法一样 |

排序、多选、分页：现在都不做，真需要时作为产品切片提出。排序要用表头里的按钮，并加上 `aria-sort`。

### 3.5 弹窗【已实现】

只有一个弹窗元素，用原生 `<dialog>` 的 `showModal()` 打开。它放编辑表单，或者一个服务的通知设置：浏览器要询问的每个地址一步，每步有标题、它管什么、以 `status` 显示的回答（被阻止时为 `alert`，用 `--error`）和一个「允许」按钮，底部只有「关闭」。回答为「已开启」后按钮消失。浏览器阻止了的地址，页面没法再次询问，所以被阻止的那一步写明去哪里打开，并且自己跟着变化更新：页面那一步指向本页地址栏左边的图标，不放按钮；推送那一步的按钮变成「打开 127.0.0.1:<端口>」，打开一个完整的标签页，因为标签页一定有地址栏。理由：不让用户自己去找一个他不知道的端口的设置。

| 部分 | 取值 |
| --- | --- |

| 类型 | 选择器 | 什么时候用 | 角色 | 样式 | 存在多久 |
| --- | --- | --- | --- | --- | --- |

- 成功用 `status`，失败用 `alert`。先写 `role`，再写文字；如果文字没变、只是紧急程度变了，就重新写一遍文字，让读屏软件再读一次（`feedback()`，在 `web/dom.js`）。

- 不用浏览器的 `alert()` 和 `confirm()`。
- 提示出现时淡入（见 1.7），消失时立即消失。

## 4 通用模式

### 4.1 页面布局【已实现】

| 视图 | 结构 |
| --- | --- |
| 总览 | 页头（16px 的 `h1` 在左；「重置布局」「添加内容」「刷新」在右，只有刷新是主按钮；换行时间隙 12px，下外边距 16px；页头随页面滚动；「添加内容」和加号卡片打开同一块添加区）→ 卡片网格（最后一格是加号卡片） |
| 页面与插件 | 页头（`h1` 和「添加内容」）→ 搜索（插件超过 10 个时出现）→ 已启用 → 已停用 → 需要处理 → 回收区 → 添加内容（表单、自带插件、接入教程）→ 插件文件夹（折叠） |
| 服务 | 工具栏（内边距 12px 16px，`--panel` 底，下边框；名称是 16px 的 `h1`；「刷新」「新标签打开」「更多操作」）→ 占满剩余高度的 iframe |
| 详情和监视 | 条目列表，见 3.11；监视视图里的卡片最大宽度 720px |

每个视图都是一个以自己标题命名的 `<section>`，里面只有一个 `h1`，标题逐级下降，不跳级。内容区只有 `main` 滚动，侧栏的插件列表单独滚动。

### 4.2 表单校验【已实现】

1. **输入时**：不校验，不在用户打字时报错。理由：服务器才是最终判断者，例如 `nas.local` 能不能解析，只有服务器知道。
2. **提交时**：先做原生校验（`required`、`reportValidity()`）。通过后禁用提交按钮，文字换成「正在保存…」，表单带 `aria-busy="true"`。
3. **被拒绝时**：服务器返回错误码，页面用词典里的文字说明问题；草稿保留；错误放在表单旁边，用 `role="alert"`。
4. **成功时**：关闭弹窗或清空添加表单，在新增或修改的那一行旁边用 `role="status"` 播报结果。

错误文字要说清两件事：哪里不对、怎样才对。例如：

> 这不是网址。请填 127.0.0.1:8080 或 http://nas.local:5000 这样的地址。

### 4.3 空状态【已实现】

- 空状态写在内容本来会出现的位置（侧栏列表、卡片网格），不只写在横幅里。
- 一句话说明为什么是空的，下一句说怎么填上，最好直接给出入口：

> 还没有卡片。到“页面与插件”添加一个，或把插件文件夹放进 {dir}，然后用 plugin reload 重新加载。

- 样式：`.empty`，`--muted`，长路径在任意位置换行。
- 总览为空时，加号卡片照样出现，这是最直接的入口。
- 搜索没有结果时，在列表的位置显示「没有匹配的页面或插件。」，同时用读屏播报命中的数量。

### 4.4 错误页【已实现】

控制台用 hash 路由，没有单独的错误页。错误显示在出问题的地方：

| 情况 | 显示在哪里 | 文字举例 |
| --- | --- | --- |
| 地址指向不存在的插件，或地址格式错误 | 回到总览，不显示 404 | — |
| 连不上后端 | 全局横幅 | 连不上 hostdeck 后端：{detail} |
| 某个插件的 `plugin.yaml` 写错了 | 保留为一个出错的条目，放在「需要处理」里，带可以展开的文件位置 | 这个插件的 plugin.yaml 有问题：{detail} |
| 某张卡片读不到 | 卡片里的 `.card-error` | 取不到数值：{detail} |
| 内嵌服务打不开，或端口被占用 | 服务视图顶部的 `#service-error` 横幅 | 端口 {detail} 固定属于这个插件，正被别的程序占用。… |
| 第一次读取一直没有回来 | 卡片网格的位置 | — |

理由：本机的控制台没有「页面不存在」的说法；用户要的是知道哪个服务出了什么问题，而不是跳到一张通用的错误页。

### 4.5 加载与骨架屏【已实现】

**不做骨架屏。** 理由：数据都在本机，大多几十毫秒就回来；骨架屏一闪而过，反而比直接出内容更晃眼。

| 情况 | 处理 |
| --- | --- |
| 第一次加载总览 | 网格的位置显示「读取中…」（`role="status"`），网格带 `aria-busy="true"` |
| 某张卡片还在读 | 这张卡片显示 13px `--muted` 的进行中文字，其余卡片照常显示；每 2 秒再请求一次 |
| 点了刷新 | 刷新按钮禁用，文字换成「刷新中…」 |
| 详情页重新读取 | 已有的内容留着，刷新按钮禁用，读完再替换 |
| 卡片的控件正有焦点 | 新读数先不显示，等焦点离开再换，免得把用户正在操作的面板冲掉 |
| 执行详情操作 | 确认后按钮禁用，文字换成「执行中…」；结果写在详情页的就地提示里，1.5 秒后重新读取列表 |
| 清除内嵌服务的缓存 | 第二次点击关闭面板，进度写在工具栏上，不写在面板里 |

## 5 无障碍与可用性

### 5.1 颜色对比度【已实现】

**下限**：

- 文字（包括 12px 和 13px 的小字）≥ 4.5:1。
- 24px 及以上，或 18.66px 及以上的粗体，≥ 3:1。
- 非文字（焦点环、控件边界、状态点、状态条）≥ 3:1（WCAG 1.4.11）。

测量方式：WCAG 相对亮度；浅底按 `color-mix(in srgb)` 混出实际颜色后再测；带透明度的浅底，按它所在的表面合成后再测。

**门禁**：三个测试，都在 `web/assets_test.go`，两种主题都测。

- `TestTheConsolesColoursStayReadableOnTheirOwnBackgrounds`：10 对纯色文字和底色，≥ 4.5:1。
- `TestWordsStayReadableOnTheTintsTheyAreWrittenOn`：16 组写在浅底上的文字。从绘制它的那条规则里读出配方，解析 `var()` 回退和 `color-mix(in srgb)`，叠到组件所在的表面上，≥ 4.5:1。规则搬了家，测试会失败，而不是悄悄不测。
- `TestFieldEdgesTheFocusRingAndStatusDotsStandOutFromTheirSurfaces`：输入框的边（平时和悬停）、焦点环、三种状态点，≥ 3:1。

**实测（2026-10-25，按 main 上的 `web/style.css`）**：

| 组合 | 浅色 | 深色 | 下限 |
| --- | --- | --- | --- |
| 「正常」/「注意」/「异常」/ 中性胶囊，10% 浅底 | 4.63 / 4.53 / 4.76 / 4.88 | 5.95 / 6.25 / 4.67 / 5.23 | 4.5 |
| 待确认按钮在指针下：`--error` 字，`--tint-error-hover` 底 | 4.62 | 4.56 | 4.5 |
| 错误提示：`--error` 字，`--tint-error-panel` 底 | 4.77 | 4.71 | 4.5 |
| 选中的导航行：`--text` 字，`--tint-active` 底 | 13.53 | 10.60 | 4.5 |
| 主按钮悬停 / 按下的文字 | 7.04 / 8.87 | 8.21 / 10.01 | 4.5 |
| 输入框的边 `--line-control`，在 `--panel` / `--bg` 上 | 3.35 / 3.12 | 3.14 / 3.50 | 3.0 |
| 输入框悬停的边 `--muted`，在 `--panel` / `--bg` 上 | 5.56 / 5.19 | 6.20 / 6.89 | 3.0 |
| 焦点环 `--accent`，在 `--panel` / `--bg` 上 | 5.61 / 5.24 | 5.88 / 6.54 | 3.0 |
| 状态点：有应答 / 没有应答（环）/ 还没有消息 | 5.32 / 5.53 / 3.35 | 7.17 / 5.37 / 3.14 | 3.0 |

胶囊那一行是在 headless Chrome 里读出计算后的颜色、合成到 `--panel` 上测的；其余按同样的公式计算，和测试一致。

几个取值的来历：

- 胶囊浅底从 16% 改成 10%。16% 时浅色四种胶囊是 4.18–4.49，深色「异常」是 4.28。10% 是让所有胶囊都过线的最小改动，但浅色「注意」只高出下限 0.03，所以必须有门禁测它。
- 待确认按钮在指针下原来借用横幅的 14% 红底，只有 4.44–4.48，所以有了自己的 12%。
- `--line-control` 是在 `--line-strong` 和 `--muted` 之间、在两种表面上都不低于 3.1:1 的最浅值，多留的 0.1 用来抵消浏览器取整。原来输入框的边是 `--line`，只有 1.17–1.37:1。
- `--line-control` 只用在输入框和状态点上，不用在按钮和卡片上。理由：按钮有文字标签，卡片有内容，WCAG 1.4.11 不要求它们的边界达到 3:1；要求的是表明「这里可以输入」的那条边。卡片和分隔线保留 `--line`，界面整体仍然安静。

### 5.2 焦点可见性【已实现】

- 全局 `:focus-visible { outline: 2px solid var(--accent); outline-offset: 3px; }`。不准写 `outline: none` 而不提供替代样式。
- 焦点在 DOM 顺序里移动，不用正数的 `tabindex`。
- 弹窗和抽屉把焦点限制在里面，关闭后焦点回到打开它们的控件。
- 获得焦点的控件消失时，把焦点移到旁边合理的控件上（比如「重置布局」消失后，焦点移到「刷新」），不能掉回 `body`。
- 跳转链接是 Tab 顺序的第一项。

### 5.3 键盘操作【已实现】

| 按键 | 作用 |
| --- | --- |
| Tab / Shift+Tab | 按 DOM 顺序在控件之间移动；关着的面板和抽屉里的控件不在顺序里 |
| Enter / Space | 按原生行为激活按钮、链接和 `summary` |
| Escape | 依次关闭操作面板、抽屉、弹窗（正在保存时除外），焦点回到打开它们的控件 |
| 排序 | 「更多操作」里的「上移」「下移」，拖动只是另一种做法 |

**不加单键快捷键**，比如 `j` / `k`。理由：内嵌的页面和输入框都要用键盘，单键快捷键会和它们冲突。

### 5.4 目标尺寸与指针【已实现】

- 能点的东西至少 44×44px。只有两个例外：`.move` 和 `.card-width`，因为它们只出现在操作面板里，而面板里的项本身就是 44px 高。
- 所有可以点的元素都设 `touch-action: manipulation`。
- 拖动有键盘替代（5.3）。拖进来的地址只有来自外部服务时才会被接受，拖动控制台自己的链接不会添加插件。

### 5.5 不只靠颜色【已实现】

- 卡片状态：状态条和边框颜色，加上写出状态词的胶囊。
- 管理行状态：写出「已启用」「已停用」等文字。
- 危险操作：红色之外，按钮文字也会变成确认的说法。
- 侧栏状态点：没有应答的是圆环，有应答的是实心点（3.13）。

### 5.6 动效【已实现】

- 尊重 `prefers-reduced-motion`（见 1.7）。
- 没有闪烁、自动轮播或视差效果。
- 动效只能告诉用户「东西出现了」或「东西去了哪」，不做装饰。

### 5.7 语义与读屏【已实现】

- 地标：侧栏是一个有名字的 `complementary`，里面是唯一的 `navigation`；每个视图是一个以标题命名的 region；`main` 可以被聚焦。
- 标题：每个视图只有一个 `h1`，往下逐级，不跳级。
- 状态：`aria-current`、`aria-pressed`、`aria-expanded`、`aria-busy` 都跟着真实状态更新。
- 外链、弹出面板、代码示例都在名字里说明自己是什么。
- 文字一律用 `textContent` 写入，不用 `innerHTML`。理由：插件提供的字符串不能被当成 HTML 执行。

### 5.8 文案语气【已实现】

**总体**：像一个懂行的同事在说明情况，说清楚、具体、平静。

| 规则 | 做 | 不做 |
| --- | --- | --- |
| 说出发生了什么，再说怎么办 | 没有设置环境变量 {detail}。带上它再启动 hostdeck。 | 出错了，请重试。 |
| 把技术细节放在冒号后面 | 布局保存失败：{detail} | 把错误码直接给用户看 |
| 用户没做错时不要求用户 | 插件现在不再对这个条目提供这个操作，列表会重新读取。 | 您的操作无效。 |
| 按钮用动词 | 刷新、撤销、添加、保存、从工作区隐藏 | 确定、OK |
| 状态用短词 | 正常、注意、异常（Problem，不用 Error） | 严重故障 |
| 进行中用「…」 | 刷新中…、正在保存… | 请稍候 |
| 语气平静 | 句号结尾 | 感叹号（现在两种语言里都是 0 个） |

**中文**：

- 不用「您」（现在是 0 处）；「请」只用在确实要求用户做事的句子里（现在有 10 处）。
- 全角标点；引用界面上的名字用中文引号，比如“页面与插件”。
- 命令、文件名、字段名保持英文原样，和中文之间留一个空格：“这个插件的 plugin.yaml 有问题”“然后用 plugin reload 重新加载”。
- 按中文的说法来翻译，不按英文逐字翻。比如状态词 Warning 译成「注意」而不是「警告」，Problem 译成「异常」，Read at {time} 译成「读取于 {time}」。

**英文**：句首大写，其余小写（sentence case），按钮也是如此；不用 can't、don't 这类缩写（所有格 's 可以用）；称自己为 hostdeck，不用 we。

**两种语言**：同一个键，意思和紧急程度必须一致；新文字两份词典一起加（`web/i18n_test.go` 会检查）。

### 6.2 样式代码组织【已实现】

`style.css` 从上到下的顺序：令牌（浅色）→ 深色令牌 → 重置和基础 → 布局 → 组件（按页面上出现的顺序）→ 进场动效 → 视口断点 → 减少动效。

规则：

- 同一个作用域里，一个选择器只写一次；每个断点只有一个媒体查询块（测试检查）。理由：后面的规则不会悄悄覆盖前面的。
- 只有两处可以用 `!important`：`[hidden]` 和减少动效的兜底规则。
- 不写行内样式。唯一的例外是面板按测量结果设置的 `left` 和 `top`。
- 不用工具类（如 `.mt-2`、`.text-sm`），也不在 JS 里写样式。理由：样式和组件写在一处，令牌刻度由测试守住，工具类会绕过这两点。

### 6.5 接入一个新组件或新视图

1. 先在本规范里找现成的组件，能用就用。
2. 只用已有令牌。确实需要新值时，按 2.5 加令牌，并在同一个 commit 里改测试里的刻度表。
3. 文字两份词典一起加；后端的新错误码也要两种语言的文字。
4. 状态用原生属性或 ARIA 属性表达（3.0）。
5. 新的颜色组合加进对比度门禁。
6. 浏览器测试覆盖 520px 和 1280px、两种语言、键盘路径；有动效的话，还要测减少动效时的情况。
7. 按 AGENTS.md 的切片流程提交：一个用户能感知到的行为对应一个分支、一个 commit 和一个 PR，取舍写在 trailer 里。
8. 本规范里对应的那一节和代码放在同一个 commit 里更新，两种语言一起改。

Docker 详情在头部使用共享的二次确认操作控件：已创建/已停止显示启动，运行中显示重启，暂停/过渡/已损坏状态只展示信息。成功操作后的标准重读保留搜索和分类选择，容器改变状态后可从当前筛选结果中移出。

定时任务详情复用紧凑分类行、既有确认操作和有界折叠日志。同一页有「任务 | 脚本」分段，当前分段只有一个主按钮：新建任务，或新建脚本。两种表单都复用现有的页面对话框。新建任务写入名称、启用复选框、五个 Cron 字段加明确时区或一个间隔、超时和一行命令。标识只展示，不是输入框。编辑和删除排在既有行操作旁边；删除沿用现有的点两次确认。空任务列表是一段带配置和示例路径的双语说明，不是计入筛选的一行。脚本复用这个对话框保存一个文本文件；保存脚本不设定时，也不运行。脚本行的「设定时」用同一个对话框打开预填了默认命令的任务表单，「运行」沿用点两次确认，跑一次且不写任务文件。结果字段区分原因、观察到的退出码与修订。任务浏览器夹具验证两种语言、两种主题及 1280／520px，不新增视觉令牌。新建任务和新建脚本还在 640px 高的窗口里把取消和保存留在视口内（`TestAShortWindowKeepsDialogActionsInView`）。

监听端口复用紧凑分组详情列表：hostdeck、本机回环、全部网卡和其他地址，带有本地化取值。条目展示端口、地址、PID、进程名、工作目录与命令行（超过 512 字符带本地化后缀截断）；未读到的目录与命令展示本地化说明字段而非空白。

内置服务观察为每个支持的条目提供“日志与状态”折叠区，没有日志正文也提供入口。二次确认后立即展开并显示“正在提交”，随后独立显示操作结果和最新运行状态。仅更新状态、来源说明、时间和有界日志正文；保留操作按钮、确认状态、焦点、筛选和滚动。可见且展开时，每次读取完成后等待一秒；失败保留内容与时间，按 2、5、10 秒退避。收起、离页和浏览器进入后台时暂停，回来立即读取。默认跟随末尾，向上滚动后暂停，“回到最新”恢复跟随。已有内容单独折叠。“最近操作”放在当前条目与计数以外，条目消失后仍可访问。`TestAnOpenObservationFollowsWithoutReplacingTheFocusedAction` 覆盖中英文、明暗主题、1280／520px 以及滚动和焦点保留。

监听端口和手动启动的服务共用同一个观察组件，输出仍在终端时也明确说明。确认操作后，仍存在的条目和控件继续复用原节点；消失的条目移到最近操作，操作按钮禁用，当前筛选计数不再包含它。浏览器测试判断结束的进程是否消失时，仅检查当前列表。

操作响应尚未返回时也可以继续读取观察。更新失败显示“未知”，同时保留上次成功的时间和正文。取消请求尚未结束便返回页面时，在该请求结束后立即补读，不再多等一轮。条目的可用操作变化时复用按钮，确认文字按当前操作生成。采集输出标明来自 Hostdeck，采集故障单独说明。`TestObservationPollingWaitsForCompletionBacksOffAndResumesImmediately` 和独立服务重新打开验收覆盖这些行为。
