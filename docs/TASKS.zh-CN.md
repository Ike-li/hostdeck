# 定时脚本任务

[English](TASKS.md)

一个已安装的插件管理多个任务。[插件协议](PLUGINS.zh-CN.md)提供卡片、详情和需要确认的操作。任务是普通本机程序，不必输出插件 JSON。调度在 hostdeck 内部运行，不增加服务或端口；关闭浏览器不影响调度，退出 hostdeck 就停止。hostdeck 不安装 launchd 或 Windows 任务计划程序条目，不下载脚本、安装依赖，也不自动重试失败的运行。详情页可以在 `tasks.json` 里新建、编辑和删除任务，也可以把脚本存成 `scripts/` 下的文本文件。保存脚本不设定时，也不运行。脚本行可以按允许的命令运行一次，或打开预填了默认命令的任务表单。保存任务会刷新这个控制台的调度，但不会启动命令。

## 文件与版本

插件文件夹里存放本地编辑的 `tasks.json`、`scripts/` 下的文本文件，以及插件自己管理的 `data/` 目录。`tasks.json` 带 `version: 1`。`data/state.json` 带 `version: 1`，保存任务运行偏好、间隔锚点、调度游标和运行记录；日志放在 `data/logs/`。这些文件只属于这个插件，不要求每个 hostdeck 插件都使用。任务的版本 1 与清单的 `schema: 1` 相互独立。

配置是一个 UTF-8 JSON 对象，最大 1 MiB，恰好一个值，对象键不能重复。未知字段、不支持的版本、错误类型、显式 null、重复任务 ID 或任何无效任务，都会拒绝整份候选配置。必填的嵌套 `schedule` 和 `exec` 必须为对象，计划必须恰好选择 `cron` 或 `every` 之一。启动时配置无效就不运行任何任务，并说明原因；重载被拒绝时保留上一份有效配置。加载、校验、读取卡片或详情都不会启动脚本。显式重载成功后，自动调度只考虑未来的触发时间。不持续监听任务文件变化。

状态在每个已安装插件唯一的操作系统所有者锁下原子写入。另一个进程可以读取快照，但锁被占有时不能调度、运行、更改偏好或修复状态。状态损坏或版本不支持时，拒绝一切执行和写入，直到本地修复；绝不悄悄覆盖。后续实现必须读取以前支持的状态版本。配置读取器拒绝不认识的字段；状态读取器可以忽略受支持版本中新增的可选字段。不兼容的配置变更需要新版本和迁移说明。

## 任务定义

根字段是 `version`（必填，整数 `1`）和 `tasks`（必填数组，0 到 64 个任务）。下列字段全部属于 `tasks.json`，不加入 `plugin.yaml`。

| 字段 | 类型／默认值 | 含义 |
| --- | --- | --- |
| `tasks[].id` | 必填字符串 | 稳定身份，1–64 个 ASCII 字母、数字、下划线或连字符，首字符为字母或数字。在该已安装插件内唯一；已删除任务的 ID 不用于另一种用途。 |
| `tasks[].name` | 必填字符串 | 给人看的名称，去掉两端空白后为 1–200 个 Unicode 码点。 |
| `tasks[].enabled` | 必填布尔值 | 是否允许自动触发和手动运行。安装插件不覆盖这个值。 |
| `tasks[].schedule.cron` | 字符串 | 五个数字字段，依次为分钟、小时、日期、月份、星期。与 `every` 互斥。 |
| `tasks[].schedule.timezone` | 字符串 | 使用 `cron` 时必填，为 `UTC` 或 `Asia/Shanghai` 这样的 IANA 时区名。使用 `every` 时不允许；不隐式采用本机时区。 |
| `tasks[].schedule.every` | 时长字符串 | 固定频率间隔，含边界的 1 分钟到 365 天，例如 `30m` 或 `24h`。与 `cron` 互斥。 |
| `tasks[].exec.command` | 必填字符串数组 | 可执行程序及分开的参数，至少一个元素，程序名不能全为空白。任何元素都不能含 NUL。 |
| `tasks[].exec.windows` | 可选字符串数组 | 规则相同，在 Windows 上替代 `command`。不写时两种系统都用 `command`。 |
| `tasks[].exec.dir` | 可选字符串，`.` | 绝对目录，或相对已安装插件文件夹的目录。执行前解析，必须存在。 |
| `tasks[].exec.env` | 可选字符串映射，`{}` | 环境变量覆盖，每个值恰好为 `${env:NAME}`，引用 hostdeck 的环境。不写明文密钥，也不插值参数。 |
| `tasks[].timeout` | 可选时长字符串，`30m` | 执行期限，含边界的 1 秒到 24 小时，包括启动。清理最多额外一秒。 |

时长使用 Go 的正数时长语法（`1h30m`，不使用日历月或 `d` 后缀）。空字符串和 null 都不代表默认值。发布配置前检查配置本身的限制；执行时再次检查目录、程序是否可用和环境引用，失败就记为失败运行，不启动脚本。

环境键和被引用名称符合 `[A-Za-z_][A-Za-z0-9_]*`。只差 ASCII 大小写的键在 macOS 上也拒绝，避免 Windows 覆盖含糊。子进程其余环境继承 hostdeck。覆盖继承键时采用目标系统的大小写规则。引用不存在会使该次运行失败；环境值不复制进保存的运行记录。这里的引用语法只属于任务的 `exec.env`，不会扩展清单允许引用的位置。

### 配置示例

下面是已支持的 v1 配置。脚本和解释器必须已经在本机存在。两个任务初始都停用，明确启用后才安排执行。

```json
{
  "version": 1,
  "tasks": [
    {
      "id": "daily-backup",
      "name": "Daily backup",
      "enabled": false,
      "schedule": {"cron": "0 2 * * *", "timezone": "Asia/Shanghai"},
      "exec": {
        "command": ["python3", "scripts/backup.py"],
        "windows": ["py", "-3", "scripts/backup.py"],
        "dir": ".",
        "env": {"BACKUP_TOKEN": "${env:BACKUP_TOKEN}"}
      },
      "timeout": "2h"
    },
    {
      "id": "collect-local-data",
      "name": "Collect local data",
      "enabled": false,
      "schedule": {"every": "30m"},
      "exec": {"command": ["node", "scripts/collect.mjs"]},
      "timeout": "5m"
    }
  ]
}
```

## 调度语义

- Cron 接受数字 `*`、列表、含边界的范围和正整数步长。范围必须递增且在各字段限制内，分钟 0–59、小时 0–23、日期 1–31、月份 1–12、星期 0–7（周日为 0 或 7）。步长作用于 `*` 或范围，例如 `*/15`、`9-17/2`；拒绝名称、宏、六段表达式、`?`、`L`、`W` 和 `#`。日期与星期均受限时，满足其一即可；否则必须满足受限的那一项。只有字面量 `*` 算不受限。在完整的 400 年公历周期里找不到匹配日期的计划会被拒绝。
- 夏令时跳跃时不存在的本地时间跳过；重复的本地分钟只在第一次出现时运行一次。不重放历史触发。时区只用于计算触发时间，记录统一使用 UTC 时间戳。
- 间隔任务在第一次同时满足已启用、未暂停时建立锚点，一个间隔后首次触发。锚点持久保存，之后按 `anchor + n × every` 触发，与完成时间无关。重启或普通暂停／恢复保留锚点。修改计划后，在新计划第一次满足已启用、未暂停时重置锚点。手动运行不移动锚点。
- 每个自动触发由任务 ID、配置修订和 UTC 应触发时间共同标识。持久游标防止重复考虑相同或更早的时间，包括系统时间回拨之后。时间向前跳或调度器延迟时，最多派发最近的一次到期触发，并且必须晚到不足 60 秒；更早的触发视为错过。错过的次数和时间范围汇总进有界的任务状态，不为每个错过的时间建立记录。
- 启动、配置成功重载和恢复时，将游标推进到当前时间，跳过截至当前的一切触发。不补跑，恢复也不立即运行脚本。首次间隔锚点在此时先建立，再推进游标。
- 每个任务最多一个活动运行，启动和清理阶段也算。运行期间到期的触发记为 `skipped`，原因为 `overlap`。新配置任务的运行时暂停偏好默认为 false。每个已安装插件最多同时运行四个任务；没有空位的到期触发记为 `skipped`，原因为 `capacity`。没有等待队列。手动运行遇到重叠或无空位会被拒绝，不建立运行；否则与自动触发使用同一个执行器。
- 自动触发和手动运行都要求配置启用且运行偏好未暂停。暂停阻止后续启动，当前运行可以完成。停止取消选定的当前运行，不暂停未来触发，也不重试它。失败和超时从不触发自动重试。

这些规则提供稳定的计划，不保证脚本副作用恰好发生一次。保存启动标记后、真正启动进程前可能崩溃；脚本改过文件后、结果保存前也可能崩溃。需要安全重复执行的脚本必须自己实现幂等。

## 执行与生命周期

执行器接收不可变的任务快照和触发来源（带 UTC 应触发时间的 `scheduled`，或 `manual`）。先占用任务和并发名额，持久保存 `starting` 记录，再启动进程。写入失败就不启动。调度器、手动控件、存储与进程执行器通过内部 Go 接口协作；这些接口和控制台 HTTP 格式不属于外部兼容承诺。

`exec.command` 和 `exec.windows` 不隐式经过 shell。只有明确调用合适的 shell，才有管道、重定向、通配符和变量展开。相对目录从已安装插件文件夹开始解析；裸程序名使用子进程的 PATH，相对程序路径从解析后的工作目录开始。不会隐式加载 shell 配置或安装解释器。`@hostdeck` 是保留名，不能作为任务程序；任务脚本不能通过此协议递归调用原生插件分派。

stdin 关闭。stdout 和 stderr 是普通字节流，不是 JSON，也不决定是否成功。退出码 0 为成功，非零为失败。启动错误算失败，没有退出码。停止和到期都会取消整个子进程树，使用插件已经需要的平台边界。父进程完成后不能留下子进程继续运行。父进程退出或取消后，清理最多一秒；无法确认清理完成时必须说明，并阻止该任务启动替代运行，直到明确恢复。卡片、详情和操作与任何插件程序一样受短期限约束；确认运行只提交工作并迅速返回，不在这个请求里执行长脚本。

重载的任务定义只影响以后运行。当前运行保留接收时的命令、目录、环境和超时。停用某个任务只阻止以后启动，当前运行可以完成。移除任务、停用或移入回收区整个插件、正常退出 hostdeck 时，取消受影响的运行；移动插件文件夹之前释放计时器、文件句柄和所有者锁。移动被拒绝后，只有验证原文件夹身份才可以恢复调度。隐藏工作区条目仍继续调度，隐藏不等于停用。

重启时，遗留在 `starting` 或 `running` 的记录改为 `interrupted`，不能算成功，也不自动重试。对应任务保持运行时暂停，直到明确恢复以确认结果不确定。某些系统上 hostdeck 意外退出后，进程可能仍存活；恢复不能结束未经核实或已复用的 PID，也不能声称旧进程已经停止。清理未确认时拒绝恢复，并说明需要在本地检查什么。其他任务可以恢复未来计划。任何替代进程启动前，必须解决所有权与清理状态。

## 运行记录与日志

任务 ID 标识配置条目。每次被接受的尝试获得独立、不透明且唯一的运行 `id`，由 1–128 个 ASCII 字母、数字、下划线或连字符组成；跳过的自动触发也有一个。配置 `revision` 是校验通过、补齐默认值但不代入环境值的任务定义的不透明标识。重启和定义不变的重载保留它，有效定义变化时更换。它标明请求的配置，不再保存一份命令或密钥。运行记录字段如下。

| 字段 | 含义 |
| --- | --- |
| `id`、`task_id`、`revision` | 运行身份、任务身份和配置修订。 |
| `trigger` | `scheduled` 或 `manual`。 |
| `scheduled_at` | UTC RFC 3339 时间戳，手动运行时为 null。 |
| `accepted_at` | 记录该次尝试时的 UTC RFC 3339 时间戳。 |
| `started_at`、`finished_at` | UTC RFC 3339 时间戳，对应事件之前为 null；没有启动进程时 `started_at` 始终为 null。中断运行的 `finished_at` 使用恢复时观察到的时间，不编造进程退出时间。 |
| `status` | `starting`、`running`、`succeeded`、`failed`、`timed_out`、`cancelled`、`interrupted` 或 `skipped`。 |
| `exit_code` | 观察到退出码时为整数，否则 null。即使终止返回退出码，取消／超时状态也优先。 |
| `reason` | 活动和成功运行时为 null；其他终态为稳定代码 `exit`、`start`、`environment`、`timeout`、`stop`、`task_removed`、`plugin_disabled`、`shutdown`、`recovery`、`cleanup`、`log_io`、`overlap` 或 `capacity`。可选诊断文字不属于稳定代码。 |
| `logs.stdout`、`logs.stderr` | `data/logs/` 下的相对文件，无可用日志时为 null。不允许绝对路径或 `..` 路径部分；通过记录定位日志，不接收调用者指定的路径。 |
| `logs.stdout_truncated`、`logs.stderr_truncated` | 布尔值，说明相应输出是否超过捕获字节上限。 |

正常变化为 `starting → running → 终态`，或 `starting → failed/timed_out/cancelled/interrupted`。`skipped` 为终态，没有进程和日志。`running` 可以恢复为 `interrupted`；终态记录不能回到活动状态。每次变化保留已观察到的时间。已停止、已超时或清理失败的尝试不能标为成功。

每个输出流保留前 1 MiB，之后继续读取并丢弃，避免日志满了堵住子进程。显示时替换无效 UTF-8，将控制序列和 HTML 当文字。该次运行引用的、已知非空环境值在捕获日志和呈现的诊断里遮蔽，包括跨写入分块的匹配。这无法隐藏脚本自行获取或变换后的密钥，脚本应避免打印这些密钥。绝不序列化实际环境。

每个插件最多保留 30 天、1,000 条终态记录。日志共享 64 MiB 上限。先清理最旧的终态历史／日志；活动运行的有界日志和启动记录不能清理。日志早于记录过期时，将对应路径设为 null。存储不能预留约定的有界空间或持久保存状态时，拒绝新工作并报告存储失败。日志读写失败会取消对应运行；清理已确认时记为 `failed/log_io`，否则记为 `interrupted/cleanup` 并暂停任务。不能把缺少持久结果说成成功。`data/state.json` 怎样保存这些记录见[状态文件](#状态文件)。

### 成功运行示例

下面的修订值用于演示，hostdeck 为每个有效任务定义分配一个。

```json
{
  "id": "run-01",
  "task_id": "daily-backup",
  "revision": "task-revision-01",
  "trigger": "scheduled",
  "scheduled_at": "2026-10-26T18:00:00Z",
  "accepted_at": "2026-10-26T18:00:00Z",
  "started_at": "2026-10-26T18:00:00Z",
  "finished_at": "2026-10-26T18:00:12Z",
  "status": "succeeded",
  "exit_code": 0,
  "reason": null,
  "logs": {
    "stdout": "data/logs/run-01.stdout.log",
    "stderr": "data/logs/run-01.stderr.log",
    "stdout_truncated": false,
    "stderr_truncated": false
  }
}
```

至少应有这些映射，非零退出为 `failed/exit` 并保留观察到的码；到期为 `timed_out/timeout`；明确停止为 `cancelled/stop`；并发自动尝试为 `skipped/overlap`，启动时间、退出码和日志路径均为 null。退出时确认取消为 `cancelled/shutdown`；停止结果不确定则为 `interrupted/cleanup`，任务继续暂停。

## 控件与信任

详情条目 ID 就是任务 ID。运行、暂停、恢复分别使用操作 ID `run`、`pause`、`resume`；停止使用 `stop:<run-id>`，包含当前运行 ID，避免旧控件停止后一次运行。操作边界重新读取并核对这个完整操作 ID，执行器在取消前再次原子核对。这些是插件自己的操作 ID，不是通用协议的字段。运行、暂停、恢复和停止通过详情操作边界确认。运行表示已接受，不代表已完成。操作的 `message` 以文字包含运行 ID，随后详情读数标明该次运行。操作程序 JSON 里没有专门的字段。暂停／恢复将运行偏好与本地写的 `enabled` 分开保存。只有两者都允许才可执行，恢复不能启用配置中为 false 的任务。停用／移入回收区不删除任务和历史，清除整个插件才一起删除。脚本接口检查控制台 Origin，并写进安全模型。它们只在已启用插件的 `scripts/` 目录里写一个普通文件。

脚本是可信本机代码，使用 hostdeck 用户的权限。解析工作目录不提供隔离，脚本能访问该用户可用的文件和网络。命令定义、环境值和工作目录仍在本地编写。详情的「脚本」分段一次新建、替换或删除该插件 `scripts/` 目录里的一个 UTF-8 文本文件。文件名只有一段：以字母或数字开头，其后是字母、数字、`_` 或 `-`，最多一个 1–8 位字母或数字的扩展名，全名不超过 64 个字符。`..`、斜杠、前导点号和符号链接会被拒绝。文件最大 1 MiB，且不能含 NUL。保存脚本不修改 `tasks.json`，不设定时，也不运行。另一个控制台、损坏的状态或未确认的清理会拒绝写入，与停用和移入回收区同一道门。

脚本行另外提供「设定时」，扩展名在本系统有默认解释器时还提供「运行」。「设定时」打开任务表单，预填文件名和该默认命令。没有默认解释器时仍然打开表单，命令留空。「运行」点两次后立刻跑一次，不写 `tasks.json`，也不建立计划。参数必须是下面的默认数组，或已加载配置里某个任务在当前平台的参数数组，且其中一段恰好是 `scripts/` 加文件名，程序名不能是 `@hostdeck`。默认参数只用于「运行」和这次预填：`.py` 在 macOS 上是 `python3 scripts/<file>`，在 Windows 上是 `py -3 scripts/<file>`；`.js` 和 `.mjs` 是 `node scripts/<file>`；`.sh` 在 macOS 上是 `bash scripts/<file>`，Windows 上不提供「运行」；`.ps1` 是 `powershell -NoProfile -File scripts/<file>`。这次运行与定时任务共用四个名额、同一套进程树清理、有界日志，并遮蔽与该参数数组相同的已保存任务里的已知环境值。没有空位就拒绝，不排队。同一个文件不能有两个正在进行的运行。若参数数组与已保存任务相同，则沿用该任务的超时、`exec.dir` 与 `exec.env`，与任务运行一致；否则超时为 30 分钟，命令在插件文件夹里带着 hostdeck 的环境运行。记录在 `data/state.json` 的可选 `scripts` 数组里，不是任务运行。刷新配置不会把它当成任务已删除而取消。对应脚本行显示最近结果和折叠日志。停用插件、移入回收区或控制台退出时，与任务一样取消。

「任务」分段只改这个插件的 `tasks.json`。表单写入名称、启用、一种计划和超时，以及当前平台的命令。命令按空白和双引号拆成参数数组，不经过 shell。Cron 是五个数字字段加明确的 IANA 时区；间隔是不带时区的 `every`。超时留空记为 `30m`。标识由名称生成，不能改；配置或已保存的运行里还在的标识不会再用。`exec.env`、`exec.dir` 和另一平台的参数数组保持原样。在 Windows 上，只有已经有 `exec.windows` 时才写它，否则写 `exec.command`，不凭空增加 `windows`。整份候选配置先校验，通过后才替换文件。表单被拒绝时文件不变。写入成功后只刷新本进程已加载的调度，不补跑，也不重启 hostdeck。删除只从 `tasks.json` 去掉该任务，历史仍在；正在运行的会因任务已移除而取消。手改文件后 `plugin reload` 仍然有效。同一把所有者锁、损坏状态和未确认的清理也会拒绝这次写入。读取任务不加锁。

## 状态文件

`data/state.json` 最大 8 MiB，根对象为 `version`、`tasks`、`runs`、`active` 和可选的 `scripts`。`tasks` 按任务 ID 保存 `revision`、`digest`、`schedule_digest`、`paused`、`anchor_at`、`cursor_at`、`missed`、`missed_first`、`missed_last` 及可选的 `eligible`（上次是否允许自动调度）；摘要不含已解析的环境值。`runs` 是上述运行记录数组，额外可选的 `diagnostic` 最多 1024 字节且遮蔽已知密钥。`active` 按运行 ID 保存私有工作进程 `pid` 和唯一 `token`，启动授权前 PID 可为 0。进程身份在脚本启动前持久保存；工作进程来自同一 hostdeck 二进制，通过私有管道传参数、环境和带类型输出。历史摘要展示最近十次运行；每个输出预览最多 20 行、8 KiB，整页日志最多 512 KiB。诊断条目使用保留的 `_diagnostic` ID。空任务列表是详情上的一段双语说明，不是任务，筛选计数也不把它算进去。说明里给出 `tasks.json` 和 `tasks.example.json` 的路径。说明和诊断条目都不提供任务操作。运行的 `logs` 含上述 `stdout`、`stderr`、`stdout_truncated` 和 `stderr_truncated`。可选的 `scripts` 记录一次性运行。每条含 `id`、`file`、`command`、`accepted_at`、`started_at`、`finished_at`、`status`、`exit_code`、`reason`、`logs` 和可选的 `diagnostic`。`file` 是脚本文件名。`command` 是当时允许执行的参数数组。这些运行与任务运行共用 `active`，因此也共用四个名额。状态读取方可以忽略 `scripts`。已结束的历史为每个文件保留最近一次，最多 64 条，保留 30 天。它们的日志使用与任务运行相同的 `data/logs/` 文件名，并一起被清理。

恢复只查询旧进程组／Job Object 是否已空，不结束未经核实的 PID；启动授权前的零 PID 标记表示脚本从未收到启动许可。未清理的进程身份占用并发名额。状态保留最多 64 个当前任务及 4 个待清理任务元数据；记录最多 1000 个终态和 4 个活动运行。过期引用先原子保存，之后删除日志；持有者锁下清理未引用日志，拒绝日志目录中的异常文件或超过 2016 个目录项。正常退出、替换目录和移入回收区先取消并释放旧工作进程。未落盘的完成结果标为中断并暂停，不能显示成功。

## 本地设置

在「页面与插件」安装「定时任务」，或执行 `hostdeck plugin install --url CONSOLE_ORIGIN --id scheduled-tasks`。安装生成空任务列表。详情显示配置和停用示例的绝对路径。「任务」分段可以新建、编辑和删除任务，这会改写 `tasks.json` 并立刻刷新调度，不必重载。「脚本」分段可以把文本文件保存到 `scripts/`；这次保存仍然不设定时，也不运行。脚本行的「设定时」打开任务表单，「运行」按允许的命令跑一次，并且不写 `tasks.json`。手改 `tasks.json` 后重载仍然有效，改 `exec.env`、`exec.dir` 和另一平台的命令要走这条路：表单会保留它们，但不提供编辑。备份 `tasks.json`，将 `tasks.example.json` 复制到它，在本地改为已存在的脚本／解释器，将引用的环境变量提供给运行中的控制台，仅启用需要的任务。执行 `hostdeck plugin reload --url CONSOLE_ORIGIN`，检查退出码及详情的诊断、下次时间。`plugin validate` 校验清单，不测试任务执行。仅刷新页面不会加载改动。只有服务器需要新环境变量时才需要安排重启。验证前保留备份，完成后仅删除这份备份。

连接帮助的插件提示词包含当前控制台的实际可执行文件、地址、绝对目录、shell 和 PowerShell 备份／重载命令及完整的停用配置示例，复用复制按钮和手动复制后备入口。详情展示当前平台实际命令、最近结果／原因／退出码／修订、十次运行摘要及最近一次有界 stdout／stderr 预览。配置或查看任务不等于验证脚本。已获授权的工作进程没有报告结果就消失时，即使进程树已清空，也将运行标为中断并暂停。另一个控制台不能停用或移入回收区仍被其他实例持有、或旧进程清理未确认的插件。
